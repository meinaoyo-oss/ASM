# SPICE 结果核验

MCP 覆盖：`partial`。当前 MCP 可静态检查网表结构、地节点、分析指令和模型引用，但不执行完整 SPICE 工作流；仍需要外部 ngspice/LTspice/仿真平台和可审计结果文件。

## 工作流

1. 固定 netlist、模型文件、参数、仿真器名称/版本、命令行、环境和文件哈希；确认结果对应当前设计版本。
2. 检查分析类型、激励源、初始条件、时间步长/频率步进、温度、容差、模型角和测量表达式是否满足验证目的。
3. 分别确认仿真是否收敛、结果是否完整、测量是否正确映射到需求；收敛只说明数值过程结束，不说明模型或电路正确。
4. 用量纲、数量级、极限情况、手算界限、参数扫描和实测数据进行交叉检查；对模型缺失、理想源和未建模寄生参数标记风险。
5. 保存原始日志和结果，不修改 netlist 或模型来消除告警；任何参数调整都产生新版本和新哈希。

## 输出

输出输入证据、收敛/警告摘要、关键波形或测量值、需求映射、 sanity check、模型限制、与实测差异和复现命令。无法复现或缺少模型时状态不得为完整通过。
